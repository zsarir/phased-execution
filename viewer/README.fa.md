# Phase Console

[English](README.md) · **فارسی**

یک کنسولِ وبِ محلی برای «اجرای فازبندی‌شده»: مرور طرح‌ها، فازها و هندآف‌ها، دیدنِ وضعیتِ زنده، کپی‌کردنِ
بوت‌پرامپتِ هر فازِ آماده، و خواندنِ آمار در سراسر کتابخانه‌ی طرح‌ها.

## راه‌اندازی

<div dir="ltr">

```bash
./start                      # from the skill directory — opens your browser
```

</div>

کلِ نصب همین است. چیزی برای `install` کردن و چیزی برای `build` کردن وجود ندارد: سرور، Node خالی است
(نسخه‌ی ‎22.6 به بالا، که TypeScript را مستقیم اجرا می‌کند) و سمتِ کلاینت، ES module بومی است با preact و
htm و marked و سه فونت که همه داخل همین مخزن قرار دارند — پس آفلاین هم کار می‌کند.

اولین صفحه می‌پرسد کدام پوشه را بخواند: هر مخزنی که `docs/plans` داشته باشد. انتخاب‌های قبلی را به یاد
می‌سپارد و هر وقت خواستید می‌توانید از پنل **Source** در ستون سمتِ چپ یا از **Settings → Source** عوض
کنید. برای ردشدن از این صفحه، پوشه را از همان اول نام ببرید:

<div dir="ltr">

```bash
./start ~/code/your-repo      # open this plan library straight away
./start --allow-writes        # also enable the guarded write verbs
./start --port 8080 --no-open # different port, don't open a browser
```

</div>

## زنده نگه‌داشتنش

کنسولی که در پیش‌زمینه اجرا شود، با بسته‌شدنِ ترمینال می‌میرد، با logout می‌میرد و با هر کرشی هم می‌میرد.
به‌جایش آن را به‌عنوان یک launchd agent نصب کنید تا با ورود به سیستم بالا بیاید و خودش برگردد:

<div dir="ltr">

```bash
./start --install-agent --root ~/code/your-repo
./start --agent-status      # is it up, and as which pid
./start --agent-log -f      # follow the structured log
./start --agent-restart
./start --uninstall-agent
```

</div>

از طرف دیگر، تلاش می‌کند اصلاً زمین نخورد. یک خطای مدیریت‌نشده، یک file watch که ارور می‌دهد، مرورگری که
وسطِ استریم ناپدید می‌شود — هرکدام به‌عنوان وضعیتِ **degraded** ثبت می‌شود و از `/api/state` سرو می‌شود،
به‌جای اینکه پروسه را بکُشد. خودِ file watch هر دقیقه خودش را بررسی می‌کند و اگر کر شده باشد دوباره ساخته
می‌شود — چون یک تابلوی یخ‌زده دقیقاً شبیهِ یک تابلوی سالم به نظر می‌رسد. هر خروجی، دلیلش را در
`~/.local/state/phase-console/console.log` می‌نویسد، و اجرایی که هیچ دلیلی ننوشته باشد، دفعه‌ی بعد که
کنسول بالا می‌آید به‌عنوان کرش گزارش می‌شود — یعنی «همین‌جوری قطع شد» سؤالی است که لاگ می‌تواند جوابش را
بدهد.

## چه چیزهایی نشان می‌دهد

| صفحه | محتوا |
|---|---|
| **Source** | هر مخزنی که `docs/plans` دارد؛ انتخاب‌های اخیر ذخیره می‌شوند و هر لحظه قابل تعویض‌اند. |
| **Plans** | همه‌ی طرح‌ها با درصد پیشرفت، فازهای آماده، قفل‌ها، رژیم QA و سلامت. تازه‌ترین فعالیت اول؛ با فیلترِ وضعیت، آماده، قفل‌شده یا مخزن. |
| **Route** | طرح به‌شکلِ نقشه‌ی مترو — فازها ایستگاه‌اند، وابستگی‌ها ریل‌اند، و هر دسته‌ی پیشنهادیِ نشست، قطاری است که از ایستگاه‌هایش عبور می‌کند. |
| **Departures** | تابلوی وضعیت: حالت، اندازه، وابستگی‌ها، گیت‌ها، قفل‌ها و QA برای هر فاز. |
| **Phase** | هدف، «اول این‌ها را بخوان»، فایل‌ها، گام‌ها، معیارهای خروج، راستی‌آزمایی، به‌علاوه‌ی هندآفِ همان فاز، وضعیت گیت، قفل و بوت‌پرامپت. |
| **Handoffs** | هر هندآف با قراردادِ front-matter، متن و بوت‌پرامپت‌هایی که تولید کرده. |
| **Analysis** | مسیر بحرانی، گلوگاه، بهترین فازِ بعدی، وزن و تعداد نشستِ باقی‌مانده، خط زمانیِ اتمام، جدول QA، مشکلاتِ سلامت. |
| **Overview** | زمینه، معماری، بودجه‌ی نشست، جدول phase-graph، راستی‌آزماییِ سرتاسری و ورودیِ حافظه‌ی طرح. |
| **Ready now** | هر فازِ آماده در سراسر همه‌ی طرح‌ها، مرتب‌شده بر اساسِ اینکه چقدر کار را باز می‌کند، هرکدام با پرامپتِ قابل‌کپی. |
| **Statistics** | جمع کلِ سبد، سرعت پیشرفت، تقویمِ اتمام‌ها، ترکیبِ اندازه‌ها، مخازن، اسکیل‌ها، مدل‌ها، قفل‌ها و همه‌ی مشکلاتِ سلامت. |
| **Autopilot** | راندنِ یک طرح بدون حضور شما: یک `claude -p` برای هر فاز، با مدل و effort و اسکیل‌ها و مجموعه‌ی ابزار که برای هر اجرا یا هر فاز انتخاب می‌شود؛ کنسولِ زنده‌ی نشست؛ صفِ تأییدها؛ و کنترل‌های pause، stop، retry، skip یا اجرای فقط یک فاز. |
| **Search** | جست‌وجوی تمام‌متن در همه‌ی طرح‌ها و هندآف‌ها، گروه‌بندی‌شده بر اساس طرح. |

صفحه خودش را به‌روز می‌کند: یک watch روی `docs/` تغییرات را با server-sent events می‌فرستد، پس هندآفی که
یک نشستِ ایجنت می‌نویسد بدون رفرش ظاهر می‌شود.

## اتوپایلوت

سوییچِ `--allow-run` به کنسول اجازه می‌دهد نشستِ ایجنت بسازد. عمداً از `--allow-writes` جداست: یک
«نوشتن» فقط اسکلتِ یک فایل را می‌سازد، اما یک «اجرا» ساعت‌ها مخزن شما را ویرایش می‌کند.

هر فاز یک پروسه‌ی `claude -p` است، پس «کانتکست را بین فازها پاک کن» اصلاً نیاز به پیاده‌سازی ندارد —
پروسه تمام می‌شود و کانتکستش را با خودش می‌برد. یک فاز فقط وقتی جلو می‌رود که **سه بررسیِ مستقل با هم
موافق باشند**: دستورهای راستی‌آزماییِ خودِ طرح پاس شوند، `validate.sh` همچنان پاس باشد، و تابلو که
**دوباره از روی دیسک** خوانده شده بگوید فاز انجام شده. هیچ‌کس از خودِ نشست نمی‌پرسد که آیا موفق بوده یا نه.

**اینکه یک فاز با چه تنظیماتی اجرا می‌شود** از سه جا حل می‌شود، به همین ترتیب: چیزی که شما برای این اجرا
انتخاب کرده‌اید، بعد بولت‌های `**Model:**` / `**Effort:**` خودِ طرح برای آن فاز، بعد پیش‌فرض‌های اجرا —
و این کار **به‌ازای هر فیلد** انجام می‌شود، پس انتخابِ یک مدل باعث دورریختنِ effort ای که طرح خواسته بود
نمی‌شود. ژورنال ثبت می‌کند که هر فیلد را کدام منبع جواب داده است.

**اسکیل‌ها.** کنسول همه‌ی اسکیل‌هایی را که یک نشست می‌تواند صدا بزند فهرست می‌کند — شخصی، مالِ همین مخزن،
و مالِ هر پلاگینِ نصب‌شده — و آن‌هایی را که انتخاب کنید به بوت‌پرامپت اضافه می‌کند، برای هر اجرا یا هر فاز.
خطِ `Skills (every session)` خودِ طرح همچنان از موتور می‌آید و به‌شکلِ ثابت نمایش داده می‌شود.

**حرف‌زدن با فازی که در حال اجراست.** ورودیِ استاندارد (stdin) نشست باز می‌ماند، پس یک سؤال فقط یک نوبتِ
دیگر در همان گفت‌وگوست، نه دلیلی برای متوقف‌کردنش:

<div dir="ltr">

```bash
btw "why did you skip the cache?"     # or the box under the session console
```

</div>

قبل از ارسال، پیام به‌عنوانِ «خارج از مسیرِ اصلی» قاب‌بندی می‌شود، تا یک جواب به تغییرِ مسیرِ فاز تبدیل
نشود.

**باخبر شدن.** نوتیفیکیشن‌های مرورگر وقتی می‌آیند که اجرا متوقف شود، پارک شود یا تمام شود — هرگز برای تکِ
تکِ فازها. متغیرِ `PHASE_CONSOLE_NOTIFY=<command>` حالتی را پوشش می‌دهد که مرورگر نمی‌تواند: با عنوان و
متنِ پیام اجرا می‌شود، تا اجرایی که بدون ناظر است بتواند به اپراتوری که خواب است برسد. اینکه یک متغیرِ
محیطی است و نه یک تنظیمِ داخلِ برنامه، عمدی است — چون یک دستور را روی همین ماشین اجرا می‌کند.

**کاری که انجام نمی‌دهد.** لیستِ `permissions.deny` به هر نشست در سطحِ CLI داده می‌شود و همان لایه‌ای است
که **حتی با مردنِ این کنسول** سرِ جایش می‌ماند — این اندازه‌گیری شده، نه فرض‌شده. اما لیستِ `ask` از یک
هوکِ HTTP رد می‌شود که **fail-open** است، یعنی اگر در دسترس نباشد اجازه می‌دهد؛ پس آن لیست حاملِ
«روالِ کاری» است و هرگز حاملِ «امنیت» نیست. صفحه‌ی Settings هر دو را نشان می‌دهد و می‌گوید کدام کدام است.
از همان‌جا فقط می‌شود قانون به `deny` و `ask` اضافه کرد: بازکردنِ دستِ یک ایجنت در ساعت ۳ بامداد باید
ویرایشِ عامدانه‌ی `~/.config/phase-console/autopilot.json` باشد.

اجراکننده همچنین دستورِ راستی‌آزمایی‌ای را که از درختِ کاری بیرون بزند اجرا نمی‌کند، مگر اینکه بتوان
نشان داد فقط-خواندنی است — `curl -X POST` و `ssh box 'systemctl restart …'` و `psql -c 'DELETE …'` همه
به یک آدم ارجاع داده می‌شوند (همراه با دلیلش)، در حالی که `docker ps` و `psql -c 'SELECT …'` همچنان
اجرا می‌شوند.

## قانونی که دنبال می‌کند

`phase-graph.sh` تنها منبعِ حقیقت است برای **done / ready / waiting**، دسته‌بندیِ نشست‌ها،
بوت‌پرامپت‌ها، رژیم QA و lint. کنسول برای همه‌ی این‌ها به اسکریپت‌های خودِ اسکیل shell out می‌کند و
هیچ‌کدام را دوباره حساب نمی‌کند. پارسِ جاوااسکریپتی فقط چیزی را پوشش می‌دهد که اسکریپت‌ها بیرون نمی‌دهند
— بخش‌های متنی، جزئیات فاز، متنِ هندآف‌ها — به‌علاوه‌ی تحلیل‌هایی که آن‌ها ارائه نمی‌دهند (مسیر بحرانی،
ارزشِ بازکنندگی، سرعت پیشرفت). فایلِ `test/engine-parity.test.ts` تابلوی هر طرح را دوباره از روی پارسِ
جاوااسکریپتی می‌سازد و ادعا می‌کند که با موتور یکی است، تا این دو خوانش نتوانند بی‌سروصدا از هم فاصله
بگیرند.

## نوشتن‌ها

به‌صورت پیش‌فرض خاموش. با `--allow-writes` کنسول می‌تواند چهار اسکریپت را اجرا کند، هرکدام پشتِ یک دیالوگ
که اول دقیقاً همان دستور را نشان می‌دهد:

| کار | اسکریپت |
|---|---|
| ساختِ اسکلتِ یک طرح | `new-plan.sh` |
| ساخت یا تعمیرِ یک هندآف | `new-handoff.sh` |
| ثبتِ نتیجه‌ی QA | `qa-record.sh` |
| گرفتن یا آزادکردنِ قفلِ یک فاز | `phase-lock.sh` |

سوییچِ `--git` هرگز پاس داده نمی‌شود، پس کنسول هیچ‌وقت کامیت یا پوش نمی‌کند — آن کار عمداً در ترمینال و
با تصمیمِ خودتان می‌ماند. ویرایشِ متنِ طرح‌ها و هندآف‌ها هم عمداً ارائه نشده؛ نوشتنِ آن‌ها کارِ ایجنت‌هاست.

سرور روی `127.0.0.1` می‌نشیند، و هر نوشتنی به هدرِ `x-phase-console` به‌علاوه‌ی یک `Origin` هم‌ریشه نیاز
دارد — چیزی که مرورگر بدونِ یک CORS preflight (که سرور هرگز جوابش را نمی‌دهد) از دامنه‌ی دیگر نمی‌فرستد.

## از روی گوشی

فلسفه‌ی یک اجرای بدون‌ناظر این است که شما دست از تماشا بردارید، و فلسفه‌ی صفِ تأییدها این است که اجرا
بتواند وسطِ کار از شما چیزی بپرسد. این فقط وقتی جواب می‌دهد که کنسول از هرجایی که هستید در دسترس باشد.

کنسول همچنان روی `127.0.0.1` می‌نشیند. چیزی که عوض می‌شود این است که یک چیزِ دیگر جلوی آن سوکت می‌ایستد،
هویتِ تماس‌گیرنده را احراز می‌کند و می‌گوید او کیست. [Tailscale Serve][serve] همان موردی است که این
قابلیت برایش نوشته شده: TLS را terminate می‌کند، تماس‌گیرنده را در برابرِ شبکه‌ی خصوصی شما بررسی می‌کند و
درخواست را با loginِ او در هدرِ `Tailscale-User-Login` به loopback فوروارد می‌کند.

<div dir="ltr">

```bash
# the console: unchanged bind, plus who may arrive through the proxy
./start --root ~/code/your-repo --allow-writes --allow-run \
        --remote your-machine.your-tailnet.ts.net \
        --remote-user you@example.com

# the proxy: HTTPS on the private network, forwarding to loopback
tailscale serve --bg --https=443 http://127.0.0.1:4123
```

</div>

| سوییچ | معنی |
|---|---|
| `--remote <host>` | به این hostname هم جواب بده، که پشتِ یک پراکسیِ احرازِ هویت‌کننده قرار دارد. قابل تکرار. بررسیِ سخت‌گیرانه‌ی `Host` را روشن می‌کند. |
| `--remote-user <login>` | یک login که اجازه دارد از آن راه بیاید. قابل تکرار، یا از طریقِ `PHASE_CONSOLE_REMOTE_USERS`. برای `--remote` **الزامی** است؛ بدونِ آن کنسول اصلاً بالا نمی‌آید. |

به‌محضِ اینکه یک hostname نام ببرید، دقیقاً دو نوع درخواست سرو می‌شود: یک `Host` لوپ‌بک بدونِ هدرِ هویت
(یعنی خودِ شما، پشتِ همین ماشین) و همان hostname نام‌برده‌شده به‌همراهِ یک loginِ مجاز (یعنی خودِ شما، از
راهِ پراکسی). هر چیزِ دیگری رد می‌شود — از جمله درخواستی که از پراکسی آمده ولی `Host` لوپ‌بک می‌خواهد
(که راهی است که یک نفر در شبکه می‌توانست با آن از بررسیِ هویت فرار کند)، و هر `Host` ناشناخته (که همان
چیزی است که یک صفحه‌ی DNS-rebinding با آن می‌آید). اگر اصلاً `--remote` ندهید، هیچ‌کدامِ این‌ها اعمال
نمی‌شود و هر درخواست دقیقاً مثل قبل رفتار می‌بیند.

**هدرِ هویت فقط به این دلیل ارزش دارد که خودِ اپ روی loopback مانده است.** اگر روی یک اینترفیسِ شبکه گوش
می‌داد، هر کسی می‌توانست خودش همان هدر را بفرستد. سوییچِ `--remote` عمداً `--host` را بازتر نمی‌کند؛
[مستنداتِ Tailscale][serve] هم دقیقاً همین نکته را می‌گوید.

**راه‌اندازیِ کامل** — آن دو سوییچِ ادمین‌کنسول، گوشی، نصب روی Home Screen که نوتیفیکیشنِ iOS به آن نیاز
دارد، هشدارهای خارج از مرورگر، قوانینِ دسترسی و یک جدولِ عیب‌یابی — در
[README اصلی](../README.fa.md#phone) آمده است.

[serve]: https://tailscale.com/docs/features/tailscale-serve

## توسعه

<div dir="ltr">

```bash
node --test "test/*.test.ts"                                            # unit tests
PHASE_CONSOLE_TEST_ROOT=~/code/your-repo node --test "test/*.test.ts"   # + integration & engine parity
```

</div>

این مجموعه‌ی تست به هیچ نصبی نیاز ندارد. تست‌های یکپارچگی رد می‌شوند مگر اینکه
`PHASE_CONSOLE_TEST_ROOT` به یک کتابخانه‌ی واقعیِ طرح‌ها اشاره کند. اما تایپ‌چک به تایپ‌ها نیاز دارد —
`tsc` بدونِ `@types/node` نمی‌تواند `node:*` را resolve کند، پس آن را در یک کپیِ موقت اجرا کنید نه اینکه
یک `node_modules` داخلِ اسکیل بگذارید:

<div dir="ltr">

```bash
cp -R server test tsconfig.json package.json /tmp/pc-tc && cd /tmp/pc-tc
npm i -D typescript@5 @types/node@22 && npx tsc --noEmit
```

```
server/   index.ts (http) · service.ts (the model) · engine.ts (script wrapper) · store.ts (files)
          parse/ (front matter, plan, handoff, folder artefacts) · analysis/ (graph, stats)
          search.ts · git.ts · memory.ts · watch.ts · writes.ts · api/routes.ts
          log.ts (structured log + exit record) · lifecycle.ts (degraded state, ordered shutdown)
web/      app.js · router.js · store.js · api.js · views/ · components/ · styles/ · vendor/ · fonts/
```
